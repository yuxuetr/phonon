# Publishing Phonon Crates

Phonon ships a workspace of crates that are versioned and released
together.

> **Status (2026-10-20): not published.** The name `phonon` on crates.io
> belongs to an unrelated project (GitGhillie/phonon_rs), so `phonon-*`
> crates would read as part of it. Re-evaluate when the maintainer decides
> to publish; first settle the naming, then confirm every name is free:
>
> ```bash
> for c in phonon-core phonon-wav phonon-io phonon-engine phonon-ai phonon-podcast \
>          phonon-video phonon-mcp phonon-server phonon-cli phonon-wasm; do
>   [ "$(curl -s -o /dev/null -w '%{http_code}' -A phonon-name-check \
>     https://crates.io/api/v1/crates/$c)" = 404 ] || echo "taken: $c"
> done
> ```
>
> Releases are git tags + GitHub Releases only.

From v0.7.0 the workspace `version` aligns with the git tag
series so external consumers can pin a single line (e.g.
`phonon-core = "0.7"`).

## One-time setup

1. Create a crates.io account and verify your email.
2. `cargo login <token>` to write your token to `~/.cargo/credentials`.
3. Add yourself as an owner on each existing crate:
   ```bash
   for c in phonon-core phonon-wav phonon-io phonon-engine phonon-ai \
            phonon-podcast phonon-video phonon-mcp phonon-server \
            phonon-cli phonon-wasm; do
     cargo owner --add <github-handle> -p "$c"
   done
   ```

## Per-release checklist

1. Bump the workspace version in `Cargo.toml` (`workspace.package.version`)
   and the matching `version = "X.Y.Z"` entries in
   `workspace.dependencies`.
2. Run the release suite:
   ```bash
   cargo fmt --check
   cargo clippy --workspace --exclude phonon-studio --all-targets -- -D warnings
   cargo test --workspace
   ./phonon-wasm/build.sh   # wasm bundle
   ```
3. Update `CHANGELOG.md` (auto-generated by `git-cliff` in CI when a
   tag is pushed; you can preview with `git cliff --unreleased`).
4. Commit + tag:
   ```bash
   git commit -am "release: vX.Y.Z"
   git tag vX.Y.Z
   git push --follow-tags
   ```
5. Dry-run the publish:
   ```bash
   ./scripts/publish-crates.sh
   ```
6. If clean, publish for real:
   ```bash
   ./scripts/publish-crates.sh --execute
   ```

The script publishes in dependency order with a 30-second sleep between
crates so each upload is fully indexed before the next dependent crate
references it.

## Crates and their publish status

| Crate            | Publish | Description |
|------------------|---------|-------------|
| `phonon-core`    | ✓       | Pure-Rust DSP core (AudioBuffer, EQ, fade, mix, normalize, LUFS, plugins) |
| `phonon-wav`     | ✓       | WAV reader/writer |
| `phonon-io`      | ✓       | Multi-format I/O: WAV/MP3/FLAC/OGG/AAC + ID3v2/Vorbis comments |
| `phonon-engine`  | ✓       | Real-time playback (cpal) + streaming TTS helper |
| `phonon-ai`      | ✓       | TTS/STT providers (OpenAI, ElevenLabs, Edge, Whisper) |
| `phonon-podcast` | ✓       | Podcast pipeline (script → tagged audio + chapters + SRT) |
| `phonon-video`   | ✓       | ffmpeg wrapper for video audio extract/replace |
| `phonon-mcp`     | ✓       | MCP server exposing Phonon to LLM agents |
| `phonon-server`  | ✓       | REST API (axum) |
| `phonon-cli`     | ✓       | Command-line frontend |
| `phonon-wasm`    | ✓       | wasm-bindgen browser bindings |
| `phonon-studio`  | ✗       | Desktop GUI (Dioxus) — heavy GUI deps, not published |
| `phonon-tests`   | ✗       | Internal integration tests |

## Notes

* `phonon-studio` is marked `publish = false` because Dioxus desktop
  builds pull system-specific dev libs that aren't always available on
  the crates.io build sandbox. It's intended to be built from the
  workspace.
* `phonon-tests` is marked `publish = false` because it contains
  end-to-end test fixtures, not redistributable code.
